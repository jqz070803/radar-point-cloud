## 1. 硬件清单

| 项 | 型号 / 参数 | 说明 |
|---|---|---|
| 雷达模块（主力） | **DEV202H**（24 GHz） | 1 发 2 收，链路已打通并完成实采 |
| 雷达 SoC（主力） | **ICL1122** | 1T2R，模块自带 MCU |
| 第二块板 | **DEV113P** | 2T4R（4 收），2026-10-19 起链路已打通并接入点云软件 |
| USB 转串口（1T2R） | **CP2102** | 装 **CP210x 驱动**（不是 FTDI） |
| USB 转串口（2T4R） | **FTDI FT232** | 装 FTDI VCP 驱动 |
| 天线 | 14 dBi；6 dB 波束 水平 ±45°、垂直 ±25° | 玩家需大致正对模块 |
| 模块尺寸 | 34 mm × 15 mm，UART，1.27 mm 排针 | — |

> 注：接线图里出现的 `D127` 丝印**不是**本组设备，勿作为依据。

### 关键含义

- **1T2R = 2 个接收通道**：可做水平方位角（AoA）测量，区分目标左右；但**没有垂直（俯仰）角通道**，**无法直接测量人体高度**。
- **2T4R = 4 个接收通道**：原则上可同时做方位 + 俯仰二维角，是「跳起 / 蹲下」更可靠的实现路径；但其**俯仰通道到物理天线高度的映射尚未确定**，不得据此宣布"可测人体高度"。
- 14 dBi 高增益天线对应窄波束（±45° / ±25°），大范围横向跑动会离开视场。
- 模块自带 MCU，算法可就地运行，不必把原始数据全部上传上位机。

## 3. 实测波形与刻度

### 3.1 1T2R（主控板，已充分实测）

| 参数 | 值 | 依据 |
|---|---|---|
| 帧周期 | **129.5 ms（≈7.7 Hz）** | 实采 5078 帧 / 657.8 s = 7.72 fps |
| 每帧 chirp 数 | 64 | 实测帧结构 |
| 每 chirp 距离单元 | 8 | 实测帧结构 |
| 接收通道 | 2 | 实测帧结构 |
| 距离分辨率 | **≈0.681 m** | 由标称带宽 220 MHz 计算 `c/(2B)`，并用站位自检佐证 |
| 最大不模糊速度 | **≈±1.535 m/s** | `λ/(4·Tc)` |
| 速度分辨率 | **≈0.048 m/s** | `λ/(2·N·Tc)` |
| 水平阵元间距 | 6.250 mm（≈λ/2） | 相位差测角 |

### 3.2 2T4R（2026-10-19 打通，刻度部分待卷尺点检）

| 参数 | 值 | 依据 |
|---|---|---|
| 雷达帧周期 | **≈520.84 ms（≈1.73 帧/s）** | 实测，比 1T2R 慢 4.4 倍 |
| 每帧 chirp 数 | 64 | 实测 |
| 每 chirp 距离单元 | **32** | 实测 |
| 接收通道 | 4 | 实测（每 chirp 连续 4 帧 = 4 RX） |
| 距离分辨率 | **≈0.150 m** | 由标称带宽 999 MHz 计算 `c/(2B)` |
| 最大不模糊速度 | **≈±0.376 m/s** | 推导 |
| 速度分辨率 | **≈0.01175 m/s** | 推导 |
| 水平阵元间距 | 5.900 mm | 推导 |

> **证据等级**：2T4R 一列为**标称波形参数推导 + 1T2R 交叉验证**（同一组公式代回 1T2R 得 0.6813 m / ±1.535 / 0.0480 / 6.250 mm，与代码常量逐项吻合），**不是卷尺实测**。
> **待补**：已知距离（1.0/1.5/2.0/2.5/3.0 m）逐点采 5 s，看距离谱峰是否落在 `round(r/0.15)`，一次实验即可区分 0.15 与 0.68 两种假设。

### 3.3 1T2R 站位自检（我方自测，2026-10-15）

站位 0.70 / 1.00 / 1.35 / 1.70 m → 距离谱峰依次落 bin **1 / 2 / 2 / 3**，
中位距离 `r_med` = 1.022 / 1.703 / 1.703 / 2.385 m。
`r_med` 恰好等于 0.6813 × {1.5, 2.5, 3.5}（bin 中心），是 `range_res ≈ 0.6813 m` 的独立佐证。

同批数据还暴露两件**尚未解释**的事，**不得当作已解决**：
① 系统偏移 **0.32~0.70 m 且不恒定**；
② 带内检出率随距离明显下降（83.9% / 97.0% / 69.5% / 27.3%）。

## 4. 由实测推导的能力边界

| 指标 | 计算 | 结果 | 设计含义 |
|---|---|---|---|
| 帧率 | 1 / 0.1295 s | **≈7.7 Hz** | 每 ~130 ms 才更新一次；只适合慢速动作，**不要设计快速反应玩法** |
| 距离分辨率 | c / (2B) = 3e8 / (2×220e6) | **≈0.68 m** | 无法精细定位手部；**避免"精确触碰/定位"玩法** |
| 速度分辨率 | λ / (2T)，λ=12.43 mm，T=64×2.02 ms | **≈0.05 m/s** | 多普勒极灵敏，**"挥手/移动快慢"是最可靠信号** |
| 水平视场 | 6 dB 波束 | **±45°** | 玩家需正对模块，左右方位可分 |
| 垂直视场 | 6 dB 波束 | **±25°** | 对上下动作容忍度低，安装高度需固定 |
| 垂直角测量（1T2R） | 无垂直通道组合 | **不可用** | **无法直接测人体高度**；跳 / 蹲 需走 2T4R 二维角或间接特征 |

**一句话总结能力画像**：擅长「有无 / 快慢 / 方向 / 远近粗分」，不擅长「精细位置」。

## 5. 数据采集

- 模块支持在板端保存数据，也可通过串口透传到上位机；
- 本项目默认走**串口透传 + 自行解析**（`radar-pointcloud/radar_protocol.py`），便于自研算法；
- 自采数据集完全可行：本项目已积累左右移动、站位、跳蹲候选等多组带真值标注的采集。

> 原始采集文件（`.bin`）体积大且含人体运动数据，**不入库**；仓库只保留派生特征表与统计报告。
